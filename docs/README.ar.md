# أسواقي — دليل التشغيل

نسخة مستقلة تحتوي على الواجهة الأمامية والخادم `server.js` وقاعدة SQLite محلية. لا تحتاج حساب ChatGPT أو خدمات الاستضافة السابقة. تبدأ بمتجر فارغ؛ بيانات الموقع المنشور لا تُنقل تلقائياً.

## التشغيل السريع

ثبّت Node.js بالإصدار 24 أو أحدث. افتح Terminal أو CMD داخل مجلد المشروع.

1. انسخ `.env.example` إلى `.env`.
2. أنشئ حساب المدير بالأمر:

```bash
node --env-file-if-exists=.env scripts/create-owner.js --email manager@example.com
```

استبدل البريد ببريدك. أدخل كلمة مرور من ١٢ حرفاً على الأقل عند الطلب؛ لن تظهر أثناء الكتابة. لا توجد كلمة مرور افتراضية.

3. شغّل التطبيق:

```bash
npm start
```

4. افتح `http://localhost:3000` وسجّل الدخول. اختر العربية من زر اللغة.

الواجهة المبنية موجودة في المجلد؛ التشغيل الأول لا يتطلب تنزيل حزم npm. إذا عدّلت الشيفرة، نفّذ:

```bash
npm ci
npm run typecheck
npm run build
npm test
npm start
```

## إعداد السوبرماركت

- **الإعدادات:** اسم المتجر، العملة، الضريبة، نص الإيصال. تتقفل العملة بعد تسجيل أول عملية محاسبية.
- **المنتجات:** الاسم بالعربية والإنجليزية، الباركود، التصنيف، السعر، الوحدة والحد الأدنى لمخزون العرض.
- **المشتريات:** استلام الكمية والتكلفة والمورد والصلاحية وطريقة الدفع. تذهب البضاعة إلى المستودع.
- **المخزون:** انقل البضاعة من المستودع إلى العرض قبل البيع. انقل المنتهي/التالف إلى قسم المنتهي لتسجيل خسارة مخزون.
- **نقطة البيع:** اختر المنتجات أو استخدم قارئ باركود يعمل كلوحة مفاتيح. حدّد نقدي أو بطاقة أو آجل، وأكمل العملية واطبع الإيصال.
- **المحاسبة:** أدخل الصندوق الافتتاحي مرة واحدة، وسجّل المصاريف وتسديد العملاء والموردين.
- **الفريق والصلاحيات:** أضف حساباً وكلمة مرور لكل موظف. الموظفون يفتحون عنوان الخادم نفسه ويستخدمون حساباتهم. رمز المفتاح أعلى الصفحة يغيّر كلمة مرور المستخدم الحالي.

المدير يصل إلى كل شيء. الكاشير يبيع ويستلم المشتريات. أمين المخزن يدير المنتجات والدفعات وحركة المخزون. المحاسب يعمل على الحسابات والتقارير والمصاريف والتسديدات. تُفرض الصلاحيات في الخادم أيضاً.

تُحفظ البيانات مركزياً في SQLite، وتُحدّث الصفحات كل ١٥ ثانية، وبعد الحفظ مباشرة. عند تعارض عمليتين، تُرفض العملية القديمة ويُطلب تحديثها بدلاً من ضياع بيانات المستخدم الآخر.

## الوصول من أجهزة أخرى أو VPS

اضبط `APP_URL` على العنوان الفعلي كاملاً. إذا اختلف العنوان عن عنوان المتصفح، يُرفض تسجيل الدخول. استخدم HTTPS وخادماً وسيطاً مثل Nginx أو Caddy عند النشر. ملف `docs/nginx.conf.example` مثال HTTP فقط ويحتاج إعداد شهادة TLS.

## التشغيل بـ Docker (الطريقة المقترحة للخادم)

الدليل الكامل بالإنجليزية: `docs/DOCKER.md`.

```bash
cp .env.docker.example .env
docker compose build
docker compose run --rm aswaqi node scripts/create-owner.js --email manager@example.com
docker compose up -d
docker compose ps
```

انتظر حتى تظهر الحالة `healthy` ثم افتح العنوان المضبوط في `APP_URL`.

**داخل شبكة المحل فقط (الأبسط):** ثبّت عنوان IP للخادم من الراوتر، ثم في `.env`:

```ini
BIND_ADDRESS=0.0.0.0
APP_URL=http://192.168.1.20:3000
ALLOWED_ORIGINS=http://localhost:3000
```

بعدها تفتح أجهزة الكاشير والهواتف المتصلة بنفس الشبكة العنوان `http://192.168.1.20:3000`.

**عبر الإنترنت مع HTTPS تلقائي:** وجّه نطاقاً إلى الخادم وافتح المنفذين 80 و443، ثم:

```ini
DOMAIN=shop.example.com
APP_URL=https://shop.example.com
TRUST_PROXY=true
```

```bash
docker compose --profile https up -d
```

يحصل Caddy على شهادة الأمان ويجددها تلقائياً.

**بدون Terminal (لوحات مثل Portainer):** ضع كلمة مرور المدير في `secrets/owner_password` واجعل مالكه المستخدم 1000، واضبط `OWNER_EMAIL` في `.env`، ثم شغّل `docker compose -f compose.yaml -f compose.secrets.yaml up -d`. يُنشأ المدير عند أول تشغيل فقط، ثم احذف ملف كلمة المرور.

الحاوية تعمل بمستخدم غير root ونظام ملفات للقراءة فقط، والسجلات محدودة الحجم. البيانات محفوظة في وحدات تخزين دائمة تبقى بعد إعادة البناء أو استبدال الحاوية. لا تستخدم `docker compose down -v` إلا إذا كنت تريد حذف البيانات عمداً.

للتحديث: `git pull` ثم `docker compose up -d --build`.

## النسخ الاحتياطي وكلمة المرور

في Docker يأخذ الخادم نسخة احتياطية تلقائياً كل ٢٤ ساعة ويحتفظ بآخر ١٤ نسخة (`BACKUP_INTERVAL_HOURS` و`BACKUP_KEEP`). لنسخة يدوية:

```bash
npm run backup
# Docker:
docker compose exec aswaqi node scripts/backup.js
```

انسخ النسخ الاحتياطية خارج الخادم بانتظام، لأنها تضيع إذا تلف القرص:

```bash
docker compose cp aswaqi:/app/backups ./aswaqi-backups
```

النسخة الاحتياطية الكاملة تحتوي قاعدة البيانات والحسابات، فاحفظها بمكان محمي. ملف JSON داخل التطبيق تصدير بيانات أعمال، وليس استعادة كاملة.

**الاستعادة:** أوقف التطبيق أولاً، ثم:

```bash
docker compose stop aswaqi
docker compose run --rm --no-deps aswaqi node scripts/restore.js --from /app/backups/aswaqi-<time>.sqlite
docker compose start aswaqi
# بدون Docker: npm run restore -- --from backups/aswaqi-<time>.sqlite
```

يفحص الأمر سلامة النسخة ويطلب كتابة `RESTORE` للتأكيد، وينقل القاعدة الحالية إلى مجلد `pre-restore-<time>` بدلاً من حذفها. كلمات المرور تعود كما كانت وقت أخذ النسخة.

**إعادة تعيين كلمة المرور:**

```bash
npm run password:reset -- --email manager@example.com
# Docker:
docker compose exec aswaqi node scripts/reset-password.js --email manager@example.com
```

## المستودع

المستودع الخاص: `github.com/engnoordesign/aswaqi`. عند كل رفع إلى `main` تُشغَّل الاختبارات وتُنشر صورة Docker خاصة على `ghcr.io/engnoordesign/aswaqi`. لا ترفع `.env` أو قاعدة البيانات أو النسخ الاحتياطية أو كلمات المرور.

## حدود هذه النسخة

متجر واحد وعملة واحدة. إرجاع كامل للمبيعات النقدية وبالبطاقة فقط؛ لا يوجد إرجاع جزئي أو إرجاع بيع آجل. البطاقة تسجيل لعملية منفذة بجهاز الدفع وليست بوابة لتحصيل الأموال. لا توجد فروع متعددة أو ربط ميزان/درج نقدي أو فواتير ضريبية مصدّقة. قاعدة الحالة مناسبة كبداية لمتجر صغير وتحتاج إعادة تنظيم للجداول عند الأحجام الكبيرة. المزامنة تحتاج اتصالاً بالخادم.

اجتازت النسخة ١١ اختباراً (قواعد العمل، الخادم والأمان، ميزات الحاوية) وبناء الواجهة والتحقق من الأنواع، وجُرّبت صورة Docker وملف Compose فعلياً: الصحة، تسجيل الدخول، حفظ البيانات بعد استبدال الحاوية، النسخ الاحتياطي والاستعادة. التجربة استخدمت صورة أساس Node 24 محلية بدل صورة Docker Hub الرسمية، ويعيد GitHub Actions الاختبار على الصورة الرسمية. لم يُجرَّب ملف HTTPS مع Caddy لأنه يحتاج نطاقاً حقيقياً.
